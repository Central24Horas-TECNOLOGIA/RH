CRÍTICO — segurança/dados (recomendação: aplicar o quanto antes, são correções pequenas de código, sem custo):
- O código de acesso à prova online pode ser descoberto por tentativa e erro (só 67.600 combinações possíveis) e não tem nenhum bloqueio contra isso — quem descobrir o código vê nome, e-mail, telefone e endereço do candidato sem precisar de login.
- Quando um candidato aceita os termos de LGPD na candidatura, esse aceite não fica gravado em lugar nenhum (sem data, sem versão do termo). E a opção de "anonimizar dados de um candidato" já existe no sistema de permissões, mas não faz nada de verdade quando usada.
- Qualquer pessoa com permissão de um módulo consegue ver/editar dado de qualquer operação/processo, não só os que ela deveria acessar (trocando o número na URL). Não é um bug pontual, é assim que o sistema de permissões funciona hoje.
- Sair da conta (logout) não invalida o acesso no servidor — se alguém pegar o token de um usuário, ele continua funcionando por até 8 horas mesmo depois do logout.
- A exportação de relatórios mostra telefone e e-mail completos de todos os candidatos, sem opção de ocultar.

ESTRUTURAL — banco de dados e desempenho (recomendação: aplicar, é o que mais atrasa qualquer coisa nova):
- 5 tabelas centrais do sistema (candidatos, processos seletivos, etc.) não têm o "projeto" delas (DDL) guardado em nenhum arquivo do projeto — se o servidor atual for perdido, ninguém consegue recriar o banco do zero só com o que está no Git.
- O Kanban de candidatos (tela mais usada no dia a dia) carrega a base inteira de uma vez sem filtro — tende a ficar mais lento conforme a quantidade de candidatos cresce.
- O script que deveria criar índices de performance no banco está quebrado (aponta para nomes de tabela/coluna que não existem mais) e nunca rodou de verdade.

QUALIDADE (recomendação: aplicar, destrava testes automáticos já escritos):
- Existe uma suíte de testes automáticos para as telas com login (Kanban, aprovar/eliminar candidato, caixa de e-mail), mas ela nunca roda de verdade porque falta uma peça técnica (um "modo de teste" para login). Corrigir essa peça reativa toda a suíte de uma vez.

VISUAL (recomendação: já autorizado no padrão de design do projeto, é limpeza):
- O sistema usa Bootstrap (framework genérico) e gradientes em várias telas, contrariando a própria identidade visual definida para o Conecta. Já existem componentes próprios prontos para substituir, só não foram adotados em todo lugar.
